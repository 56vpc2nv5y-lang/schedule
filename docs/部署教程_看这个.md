# 部署上线完整教程（从零到能用网址访问）

目标：把这个看板变成一个网址（比如 `https://schedule-xxx.vercel.app`），
换电脑、换手机都能打开，数据存在云端不会丢。

全程**不需要敲命令**。分三步：GitHub（存代码）→ Vercel（跑起来）→ 填配置。
Supabase（数据库）你已经弄好了，跳过。

---

## 预备：三个你已经有的东西（等下要用，先复制到记事本备好）

打开项目里的 `.env` 文件（右键 → 用记事本打开），把下面这几行的**引号里的值**复制出来备用：

| 名字 | 在 .env 里对应哪一行 | 说明 |
|------|---------------------|------|
| `DATABASE_URL` | 第 2 行 `DATABASE_URL="..."` | 数据库连接串（6543 那个） |
| `DIRECT_URL` | 第 5 行 `DIRECT_URL="..."` | 数据库直连串（5432 那个） |
| `APP_PASSWORD` | `APP_PASSWORD="sunny"` | 登录密码，现在是 sunny |
| `DEEPSEEK_API_KEY` | `DEEPSEEK_API_KEY="sk-..."` | AI 助手密钥 |
| `DEEPSEEK_MODEL` | `DEEPSEEK_MODEL="deepseek-chat"` | 可选 |

> ⚠️ `.env` 这个文件**绝对不能上传到 GitHub**（里面有密码）。
> 别担心，项目已经设置好自动忽略它，下面的方法都不会传上去。

---

## 第一步：把代码传到 GitHub

代码要先放到 GitHub，Vercel 才能读到它。有两种方法，**强烈推荐方法 A**，简单又安全。

### 方法 A（推荐）：用 GitHub Desktop 桌面软件（不用命令行，自动排除敏感文件）

1. 下载安装 **GitHub Desktop**：https://desktop.github.com （一路下一步）。
2. 打开它，用你的 GitHub 账号登录（没有就点注册，免费）。
3. 顶部菜单 **File → Add Local Repository**（添加本地仓库）。
4. 选择这个项目文件夹 `D:\gsafety\schedule`，点添加。
   - 如果它提示"这不是一个 Git 仓库，是否创建"，点 **Create a repository / Initialize**。
5. 它会列出要提交的文件。**你什么都不用勾选，它已经自动排除了 `node_modules`、`.next`、`.env`**（因为项目里有 `.gitignore` 规则）。
6. 左下角填一个提交说明，比如 `first commit`，点蓝色 **Commit to main**。
7. 右上角点 **Publish repository**（发布仓库）：
   - 名字随便，比如 `my-schedule`
   - **务必勾选 Keep this code private（保持私有）** —— 因为虽然 .env 没传，但代码是你个人的。
   - 点 Publish。
8. 完成！代码已经在 GitHub 上了。

> 以后你在本地改了东西想更新线上：打开 GitHub Desktop → 填个说明 → Commit → 右上 **Push origin**，
> Vercel 会自动重新部署，几十秒后网址就更新了。

### 方法 B：GitHub 网页版上传（如果不想装软件）

网页版**不会自动排除大文件**，所以上传前要手动处理，否则会又慢又可能失败：

1. 先在项目文件夹里，把这两个文件夹**剪切出去**放到别处（比如桌面临时放）：
   - `node_modules`（几万个文件，非常大，不能传）
   - `.next`（构建缓存，不用传）
   - 剪走它们不影响，以后双击 `start.bat` 会自动重新生成。
2. 确认文件夹里**没有** `.env`。如果有，也先剪切出去（里面是密码）。等下 Vercel 里单独填。
3. 打开 https://github.com → 登录 → 右上角 **+** → **New repository**：
   - 名字 `my-schedule`，选 **Private（私有）**，点 Create。
4. 新仓库页面点 **uploading an existing file**（上传现有文件）。
5. 把项目文件夹里**剩下的所有文件和文件夹**一起拖进去（`src`、`prisma`、`public`、`package.json`、各种 `.bat` 等）。等它传完。
6. 下方点 **Commit changes**。
7. 传完后，把第 1、2 步剪走的 `node_modules` / `.next` / `.env` 放回项目文件夹（本地还要用）。

---

## 第二步：在 Vercel 上部署

1. 打开 https://vercel.com → 点 **Sign Up / Log In** → 选 **Continue with GitHub**（用 GitHub 账号登录，这样能直接读到你的仓库）。
2. 登录后点 **Add New… → Project**。
3. 在列表里找到刚才的仓库 `my-schedule`，点它右边的 **Import**。
4. 进入配置页，**Framework 会自动识别成 Next.js**，不用改。
5. 展开 **Environment Variables（环境变量）**，把预备步骤里备好的值一条条加进去
   （左边填 Name，右边填 Value，每填一条点 Add）：

   | Name | Value |
   |------|-------|
   | `DATABASE_URL` | 粘贴你 .env 里 6543 那串（整串，含 `?pgbouncer=true`） |
   | `DIRECT_URL` | 粘贴你 .env 里 5432 那串 |
   | `APP_PASSWORD` | `sunny` |
   | `DEEPSEEK_API_KEY` | 粘贴 `sk-` 开头那串 |
   | `DEEPSEEK_MODEL` | `deepseek-chat`（可选） |

   > 这几个就够了。文件上传用的 `SUPABASE_*` 三个暂时不用填。
6. 点 **Deploy**。等 1～3 分钟（它在安装依赖、构建）。
7. 看到 🎉 恭喜页面 + 一个网址（`https://my-schedule-xxx.vercel.app`），点它就能打开。
8. 打开后会让你输密码，输 **sunny** 进入。你之前灌进数据库的项目、任务都在。

## 常见问题

**Q：部署失败 / 红色报错？**
最常见是环境变量没填全或粘错。到 Vercel 项目页 → **Settings → Environment Variables** 检查那 4~5 条对不对（尤其两串数据库连接串别粘串行）。改完到 **Deployments** 页点最新一条右边 **⋯ → Redeploy**。

**Q：网址打开是空的 / 报"表不存在"？**
说明云端数据库还没建表或没数据。表你本地已经建好了（Supabase 是同一个云库，Vercel 连的也是它），所以正常不会。若真遇到，本地双击 `db-init.bat` 再 `db-seed.bat` 一次即可（它们操作的就是这个云库）。

**Q：以后想改密码 / 换 AI key？**
两种方式：
- 线上：登录后进 **设置** 页直接改（存数据库，立刻生效）。
- 或改 Vercel 的环境变量后 Redeploy。

**Q：数据安全吗？**
数据在 Supabase 云库，代码仓库是 Private。建议每隔一段时间到**设置页 → 导出 JSON** 存一份到自己电脑做备份。

**Q：本地还想继续用吗？**
可以，本地和线上连的是同一个云数据库，数据是通的。本地双击 `start.bat` 即可。

GitHub Desktop 发布代码 → Vercel 导入仓库 → 填 4 个环境变量 → Deploy → 用 sunny 登录。以后改代码就 Push 一下，线上自动更新。
