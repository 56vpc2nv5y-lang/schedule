## 7. 产品需求总目标

这个工具不应该是普通项目管理软件。它应该是 Sunny 的“个人工作操作台”：

- 打开首页 10 秒内知道：我现在最该干什么。
- 周报不用重新回忆：系统能按项目、日期、成果和证据自动整理。
- 简历不用临时编：每个项目做完就能沉淀成可复用能力点。
- 临时活不丢：说一句或贴一张截图，AI 能自动拆成任务、排进今日/周计划。
- 项目不是线性的：允许反复追问、客户反馈、供应商补材料、暂停和重启。

## 8. P0 级需求：必须优先稳定

### 8.1 数据库和页面不能再报错

要求：

- Prisma schema、数据库迁移、种子数据和线上/本地库必须同步。
- 缺表、缺字段、保存无反应、文件上传报错都应作为 P0。
- 每次调整模型后需要有明确的迁移脚本和验证步骤。

### 8.2 项目状态只有一个权威来源

问题：

- 之前乌兹项目同时出现“进行中”“PAUSED”“postpone待重启”，需要用户自己拼真实状态。

要求：

- 顶层只保留一个“项目状态”：进行中、暂停、已完成、已取消。
- 项目列表、详情页、日历、任务列表、操作日志都读取同一个字段。
- 当前阶段只是子说明，例如“暂停 · 筹备阶段已冻结 · 等待重启复核”。
- 状态切为暂停后，日历隐藏未完成的原执行安排，但保留历史已完成记录和暂停复核任务。

### 8.3 任务列表必须覆盖真正要做的事

要求：

- 阶段 checklist、接待 checklist、纪要追问都要同步到统一任务表。
- checklist 勾选完成时，对应任务自动完成。
- 任务列表支持按来源筛选：手动新建、项目阶段、培训清单、接待清单、纪要追问。
- 今天页面右侧待办可直接打勾，状态自动同步到来源模块。

### 8.4 今日视图分组

要求：

- 今日待办拆成“项目任务”和“个人/行政事务”。
- 逾期项目任务强提示。
- 行政事务单独放，不和项目任务混排抢位置。
- 今日页面核心不是信息量大，而是快速判断“现在干什么、下一步干什么”。

### 8.5 日历对暂停项目的规则

要求：

- 已完成的历史任务永远保留，因为它们是周报和简历证据。
- 暂停项目未完成的原执行日程应隐藏或降级显示，避免误导。
- 暂停期间只显示“复核/等待/重启”类任务。
- 项目恢复进行中后，再恢复正常排期。

## 9. P1 级需求：提高工作效率

### 9.1 AI：说完就进看板

目标：

Sunny 输入一段自然语言，例如：

> 今天我处理了北理工回复；追问了樊老师；准备了接待议程

AI 应该自动完成：

- 识别所属类型：项目、培训、接待、展会。
- 让 Sunny 选择或确认挂到哪个项目。
- 用分号或自然停顿拆成多个子任务。
- 判断是否是已完成、待办、等待回复、需要追问。
- 默认截止日期为当天，除非文本里有明确日期。
- 自动进入任务列表和周计划。
- 同时生成一条成长档案草稿，供 Sunny 确认是否保存。

### 9.2 AI：截图和聊天记录识别

目标：

- 支持上传截图、聊天记录复制文本、Word/Excel 文件。
- AI 自动识别时间、人物、项目、任务、状态和证据。
- 不能确定时标注“待确认”，不要强行猜。
- 识别出 @Sunny、晓卉姐、施嘉姐、杜总、Muru、樊老师、北理工老师、曲总等关键人物时提高权重。

### 9.3 AI：周报生成

要求：

- 按周自动汇总完成事项、进行中事项、风险/待协助事项、下周计划。
- 支持按领导喜欢的口径输出：简洁版、正式版、项目版、个人复盘版。
- 周报来源必须可追溯到任务、日程、会议纪要、上传文件或成长档案。

### 9.4 AI：简历对话与收藏

问题：

- 直接生成简历点容易写得空、像模板、缺少证据。

要求：

- 新增“简历对话”按钮。
- AI 不应直接给最终版，而应先判断经历类型、追问缺失信息，再产出中英文版本。
- 每个写得好的 point 可以点“收藏”，进入 ResumePoint 素材库。
- 收藏内容支持按能力标签筛选：数据分析、项目运营、国际协作、技术沟通、解决方案、商务流程。

### 9.5 纪要与问题生成任务

要求：

- 纪要/问题状态为“不清楚需追问”或“需开会讲解”时，旁边显示“生成任务”。
- 生成任务时自动带入问题内容、项目名、来源、建议截止日期和联系人。
- 任务完成后回写纪要状态，避免“记完就断”。

### 9.6 培训项目模板

培训类项目不能套普通项目线性阶段，应使用专属流程：

1. 课程大纲
2. 核算成本
3. 报价
4. 合同签署 / 招标采购
5. 筹备
6. 异常分支：客户 postpone 后的重启复核

培训卡片至少包含：

| 字段 | 说明 |
| --- | --- |
| 当前阶段 | 大纲、核算、报价、合同、筹备、暂停 |
| 客户对接人 | 姓名和联系方式 |
| 主题数和时长 | 几大主题、总天数、每日时长 |
| 预算和费用归属 | 谁出机票、酒店、交通等 |
| 报备清单状态 | 身份证/护照/电话/名单是否收齐 |
| 合同状态 | 内部合同、客户合同、采购流程 |
| 暂停标记 | 是否 postpone，以及重启前三项复核 |

### 9.7 更轻的编辑方式

要求：

- 很多位置应支持点击即编辑，例如任务标题、截止日期、阶段说明、联系人、状态。
- 不要每次都进入复杂表单。
- 对危险操作如删除、取消项目、覆盖文件再二次确认。

## 10. P2 级需求：体验和设计

### 10.1 工作台要减负

问题：

- 现在信息容易密密麻麻，不符合“快速知道最近在干什么”的目标。

建议：

- 首页第一屏只显示：当前最重要的 3 件事、等待别人回复的 3 件事、本周风险、最近完成。
- 项目详情和任务详情再承载复杂信息。
- 行政杂事和项目推进分区，不混在同一条列表里。

### 10.2 甘特图和项目看板

问题：

- 季度看板太碎，像把每个小动作都铺到图上，反而不方便。

建议：

- 甘特图第一层只显示阶段/工作包，不显示每个微任务。
- 点击阶段后再展开子任务。
- 支持“反馈循环”显示：客户提问、供应商回复、Sunny 核验、追问、再次回复。
- 对安全检测、电动车这类项目，要允许螺旋式推进，而不是假装线性推进。

### 10.3 项目生命周期的计算

要求：

- 生命周期进度不能只按阶段数量平均。
- 应综合：阶段权重、关键交付物完成度、当前风险、是否等待外部回复、是否暂停。
- 对暂停项目，进度不应继续自动增长。
- 对反馈循环项目，进度应体现“已完成主交付，但仍在问题闭环中”。

### 10.4 动态时间线来源

要求：

- 动态时间线必须说明来源：任务完成、阶段变更、纪要更新、文件上传、AI 记录、手动日志。
- 不能凭空生成“看似合理”的历史。
- 每条时间线最好能点击回到原始任务/文件/纪要。

### 10.5 皮肤与视觉

用户反馈：

- 蓝墨蓝图太蓝、刺眼，应删除。
- 活泼、落日等皮肤图片区域配色不舒服。
- 皮肤选择可以去掉名称，只保留小圆点。
- 整体希望回到更柔和、耐看的旧配色。
- 可以探索古风和 Outlook 风格，但必须克制，不要冲击眼睛。

建议方向：

- 默认皮肤：低饱和暖白 + 柔和蓝/灰，适合长时间办公。
- Outlook 风格：浅灰蓝、清晰分割线、密度适中、按钮低饱和。
- 古风风格：宣纸白、墨灰、淡竹青/朱砂点缀，但不要大面积仿古纹理。
- 皮肤不是越花越好，重点是可读性、层级和耐看。

### 10.6 上传与 App 化

要求：

- 恢复或重建直接上传文件功能，支持 Word、Excel、图片截图、聊天记录文本。
- 上传失败要显示明确原因，不能只有报错。
- 后续可做 PWA：让本地网页像 App 一样安装到桌面，打开后自动进入看板。
- 登录可以为本地单用户模式内嵌密码 sunny，减少重复登录。
